# Panel (`/app`)

Screens for the operator: **Decisions** (the AI's questions and failures), **Tasks** (list and detail, with "Request change") and **New task** (a source card by its key, or a free task with attachments). It works on a phone (tabs at the bottom) and on a desktop (side navigation, list and detail side by side).

On the desktop there is also the **Office** tab: a pixel-art room per company, with one character per role (Architect, Coder, Tester, Fixer, Security, Reviewer, Delivery). Each active task is a folder with the card number that walks to the desk of its current stage; whoever is working moves and shows the card and the AI in use. Questions and failures wait at the "Waiting for you" counter, tasks without AI quota in the kitchen, and the last 8 PRs are on the board. Click a folder or a character to see the task. When a decision waits for you (in any company), a quest-like window pops over the map with the newest one: **Answer** opens its screen, **Later** hides it for this session. The "Demo" button moves example folders, without spending AI. Art: Kenney "Tiny Dungeon" and "Tiny Town" (CC0), downloaded by `scripts/office-assets.sh`.

## Access

- Address: `https://<your ngrok domain>/app/` (on the first visit of each browser ngrok shows a warning: click "Visit Site").
- Login: a password (its hash lives in `WEB_PASSWORD_HASH`, generated by `npm run web:password`) and then the 6-digit code sent to Telegram. The session lasts 30 days; "Sign out" ends it on the server.
- On a phone: browser menu → "Add to home screen".

## Build and publish

```bash
npm run build:web              # installs and builds web/ into web/dist
systemctl --user restart ai-dev-team-api
```

The API serves `web/dist` at `/app`. Without a build, `/app` answers 503 with the instruction above.

## Develop

```bash
cd web
npm run dev                    # http://localhost:5173/app/ (proxy to the API on port 3000)
npm test                       # Vitest
```

The Vite proxy presents the API's origin (`http://localhost:3000`), an accepted origin for session actions.

## Live updates

The panel opens `/api/events` (SSE). Each change of a task, revision or decision reloads the affected company. If the connection drops, the panel retries after 1 s, 2 s, 4 s… (up to 30 s) and reloads everything.
